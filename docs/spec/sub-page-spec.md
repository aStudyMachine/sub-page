## Problem Statement

Obsidian 自带的文件浏览器只反映磁盘结构，不反映「页面」这层概念。我的笔记库里，一层目录嵌一层目录，笔记散落在最深处；想在某个主题下加一篇子笔记，得先在文件浏览器里找到对应目录、再新建文件、再手写链接把父子关系记回去，稍不注意就漏。MOC 索引文件越写越长，每加一篇笔记都要同时改三四处（笔记本身、专题 MOC、首页表格、维护记录），忘了任何一处导航就断了。

我想按 Notion 那样组织笔记：一个页面下面直接挂子页面，点一下就看到有哪些子页面，想加就加、想改名就改名、想换个位置就拖过去，父子关系由结构本身表达，不需要我再去维护索引文件。

但现有的三个库（Knowledge 26 篇、Marcus-WIKI 24 篇、My-Resume 329 篇）里没有任何一个采用「目录 + 同名笔记」的写法，全是「文件夹里放普通笔记」。任何要求我先改造目录结构才能用的方案，我都不会用。

## Solution

一个侧栏面板，把页面根下的笔记渲染成一棵可展开的页面树，支持新建、改名、移动、删除、拖拽排序，并在页面正文里提供一个 ```subpages 代码块显示当前页面的子页面列表。

关键点：**不需要改造现有库**。页面根内的任意笔记都是页面；如果它恰好有同名目录，它就升级为父页面，目录里的笔记成为它的子页面；没有同名目录，它就是叶子页面。所以打开现有库，树直接就出来了；想让某个目录变成「父页面 + 子页面」，一个命令补齐配对即可，原有笔记一个都不动。

侧栏与正文块共用同一套页面服务，行为完全一致；所有写操作都带校验与失败补偿，删除默认进系统回收站，任何失败都会在界面上告诉我发生了什么。

## Implementation Decisions

### 领域模型（ADR-0001）

页面根下递归扫描，每个目录产出三种节点之一：**父页面**（目录内有同名笔记）、**叶子页面**（任意笔记，无同名目录或同名目录内无页面）、**分组目录**（无同名笔记但含页面后代）。不含任何页面后代的目录为忽略目录，默认隐藏。

页面模型只有一种（页面），配对是可选升级动作而非存在前提。这是采用门槛所在：现有三个库零配对也能直接成树。

非 Markdown 文件一律不进入页面树，也不产生异常；父页面目录内放附件不影响任何判定；删除页面默认不碰附件；重命名页面不改附件名、不改正文里的附件引用。

### 标识与路径（ADR-0002）

页面 ID 是不透明品牌类型，当前编码为相对页面根的路径（去扩展名、统一分隔符）。业务代码不得解析或拼接 ID；路径与 ID 的互相换算只允许出现在一个模块内。改名导致的 ID 变化由操作层主动迁移展开态、选择态、顺序表条目三处状态。

路径拼接、分隔符、大小写冲突、名称合法性判定全部收敛到路径工具模块，业务模块不得自行拼字符串。

### 分层与边界（ADR-0003）

界面（视图、行、卡片、菜单、弹窗）只依赖页面服务，不出现任何档案库或文件管理器的直接调用。页面服务之下是操作层 → 仓储层 → 适配层，适配层是与宿主 API 的唯一接触点，并被抽象成接口。

操作层每个动作统一为四段式：**校验 → 执行 → 刷新 → 补偿**，返回结果类型而非抛异常。

### 顺序持久化（ADR-0004）

顺序集中在页面根下的一个隐藏 JSON 文件，一个文件记录所有作用域：键是父作用域 ID，值是子项名称数组。存名称不存索引，因此改名只需替换一个元素、移动只需跨数组搬运，一次拖拽只写一个文件。未列出的子项按自然排序排在后面，所以手工新建的文件不会消失。解析失败时备份原文件、退回名称排序、给出可点击的警告，绝不因此拒绝显示树。写入触发的事件需自写抑制。

### 索引与刷新

启动时在布局就绪后做一次深度优先遍历，直接读目录子项而非全库文件列表，纯内存操作。遍历分片让出主线程，避免大库卡顿；超过阈值时界面显示建立索引中的提示。档案库事件只标脏，防抖后重扫受影响的最深作用域子树；脏范围过大时全量重扫。操作层自己发起的写入通过抑制集合过滤掉回声事件。页面笔记被外部修改时只刷新该节点的元数据，不重扫树。

### 界面契约

侧栏视图为单例：先查找同类型已存在的叶子再显示，没有才创建。展开状态以页面 ID 数组持久化到插件设置，索引重建后按 ID 恢复，不存在的 ID 丢弃。

树容器标注为树，行标注为树项并携带层级与展开状态；焦点采用漫游式 tabIndex 而非每行都可聚焦。键盘映射：上下移动焦点、向右展开或进入、向左折叠或回到父层、回车打开、F2 重命名、Delete 删除。

拖拽仅桌面启用，落点三种语义：落在节点上成为其子页面、落在两行之间成为同层兄弟并重排序、落在空白区移到顶层。拖入自身后代必须被拒绝。移动端以长按菜单替代拖拽，排序走菜单命令。

图标元数据支持 emoji 直出与矢量图标名前缀两种形式，未知前缀原样显示。

### 正文块

代码块语言为 `subpages`，注册时置于较高优先级。父页面定位一律依据渲染上下文提供的源文件路径，绝不读当前活动编辑器。配置支持视图形态、排序方式、是否显示图标、是否显示描述、列数，未知键收集为警告而不报错。

两种视图都渲染内容；新建、改名、删除等交互按钮只在阅读视图保证可用，实时预览下渲染只读列表并给一行切换提示。

块的空状态分三种：无子页面、当前笔记不是父页面（提供创建目录动作）、块被嵌套引用（提示不支持）。

### 设置与本地状态

插件设置只存偏好与界面状态：页面根、默认视图、默认排序、是否显示空目录、删除前确认、模板路径、语言、展开态、排除目录名。绝不存树结构。

一次性教学标记（首次引导是否已显示、拖拽提示、折叠原生树提示）存宿主本地存储而非插件设置文件，因为它们不是用户配置，且在「恢复默认设置」时不应被清掉；读写异常全部吞掉。

设置需要一个迁移入口，返回迁移后的设置与是否发生变化两个结果，即使当前只有两个字段也要有这层，否则第一次改字段名时用户配置会被静默重置。

### 文案

文案采用键值表而非双参数直传，支持插值。缺键时回退为键名本身并只警告一次。命令面板标签在注册时确定，因此切换语言需要先移除命令再重新注册。

### 版本与发布

版本号从 0.0.1 起，每个里程碑递增，全部验收通过后对外发布 1.0.0。版本号必须同时存在于三个文件中，并提供脚本一次性同步三处与锁文件，不得手改。

发布产物只有三个文件，均不入版本库；社区目录读取发布资产而非仓库文件。代码侧守卫需在创建发布之前拦截已知的 Error 级规则：静态字面量样式赋值、原生元素创建、样式表中 `!important` 声明超阈值。

### 宿主共存

与自带文件浏览器并存，提供命令折叠原生文件浏览器，不修改核心插件状态、不注入样式片段。与 Folder Note 类插件功能重叠，仅在诊断信息中提示，不主动禁用、不弹窗阻拦。

## Testing Decisions

### 什么算好测试

只测外部行为，不测实现细节：给定一组文件系统状态和一次操作，断言磁盘上最后的文件结构、以及索引对外暴露的树形结果。不针对私有方法、内部字段名、调用次数断言（事件防抖的「只重扫一次」属于可观察外部行为，可以断言）。

### 唯一的接缝

**适配层接口**是唯一测试接缝，也是全项目最高的接缝。扫描、索引、顺序存储、操作层、结构检查全部依赖这个接口，不依赖宿主。测试用内存假库实现同一接口，可在 node 环境直接跑，不需要启动 Obsidian。

现有代码库里没有先例（项目尚未初始化），接缝为本项目新设。这是**唯一**新增接缝；界面层不设接缝，靠手动验收清单。

不做浏览器自动化：宿主的视图与拖拽没有稳定测试入口，成本远超收益。

### 被测模块

- 路径与标识：根、单层、深层、中文、空格、特殊字符、大小写、后代判定（自反、兄弟、父子、跨根）、作用域归属。
- 扫描器：父页面、叶子、分组、忽略四类；同名笔记与目录并存；扩展名大小写；空目录；深层嵌套；同一目录内命名冲突。
- 名称校验：非法字符、保留名、首尾空格与点、长度上下限、同级大小写冲突、全角标点放行。
- 顺序存储：读写往返、缺省排序、未知条目忽略、损坏文件降级、自写抑制、改名迁移、移动迁移、删除清理。
- 操作层：建、改、移、删各自成功路径与失败补偿；移入自身后代被拒；目标重名被拒；删除父页面保留子页面；连带删除走回收站。
- 正文块配置解析：空块、未知键、非法枚举值、部分配置与默认值合并。
- 结构检查：未配对目录、孤立顺序条目、大小写冲突的识别。

### 集成测试

在本地观察库的临时副本上跑完整场景序列：建三层 → 改名（含中文与空格）→ 移动 → 补齐配对 → 解除配对 → 删除 → 事件到达后索引与磁盘一致。失败补偿用注入错误的方式验证（让重命名在第二步抛错，断言第一步已回滚）。

### 手动验收

每个里程碑一张清单，写进贡献指南，勾完才算完成。性能用生成脚本产出 100/1000/5000/10000 篇的假库，记录首扫、首屏渲染、展开、新建、移动、重扫耗时与内存增量，先测再决定是否需要虚拟列表。

## Out of Scope

- UUID 页面 ID（ADR-0002 已否决）。
- 页面正文全文搜索（宿主全局搜索已覆盖）。
- 拼音或模糊搜索。
- 多选与批量操作（批量移动的合法性校验与部分成功报错成本远超收益）。
- 操作撤销栈；删除靠回收站恢复，改名与移动靠反向操作。
- 往用户笔记正文注入面包屑或其他内容。
- 实时预览下的内联新建输入框。
- 云同步冲突解决逻辑，交给用户与同步工具。
- 自动删除任何用户文件；结构检查只报告、修复需确认。
- 浏览器自动化测试。
- 图表渲染、导出等与 clean-mermaid 重叠的能力。

## Further Notes

### 已实测的环境事实

本机运行 Obsidian 1.15.1，语言声明最低版本不低于 1.15.0，声明式设置需要 1.13 以上的类型定义。三个真实库的目录与笔记规模、笔记规范（frontmatter 字段、标题层级、附件集中在根目录 `_assets` 并用 wikilink 引用）已确认，可作为验收夹具的参考。

三个库中配对目录数量为零，这是把页面模型从「必须配对」改成「三类节点」的直接依据，也是本 spec 最关键的一条结论。

### 从既有项目继承的教训

宿主中 `aria-label` 就是提示气泡的来源，不得同时设置原生 title 属性。代码块处理器重复注册会抛异常，注册必须容错。声明式设置项的容器是横向弹性布局，块状内容需显式改为纵向并覆盖空与非空两种状态。社区审阅的 Error 级结论会让插件在目录中不可检索，且同版本重发不会重算，只能升版本——因此宁可把已知规则前置成构建期守卫。

### 尚未闭环的问题

- 远端仓库暂不创建，等需要运行发布流水线或需要备份时再定。
- 插件与宿主原生树的默认关系（是否首次引导用户折叠）待首次实机体验后决定。
- 本地计划目录是否入库待定：既有项目的忽略规则会把 `.agents/` 下除技能目录外的内容整体排除。
