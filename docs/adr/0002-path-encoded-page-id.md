# ADR-0002：页面 ID 采用「路径编码 + 单一换算模块」，不引入 UUID

- 状态：已采纳
- 日期：2026-11-16

## 背景

页面需要一个稳定标识，用于展开态持久化、选择态、以及将来可能的页面引用。

两种候选：
- **UUID 写进 frontmatter**：跨库移植稳定，但启动时要读取每一篇笔记的 frontmatter；1 万篇时是秒级白屏。同时「路径」与「frontmatter」构成两个真相源，外部改名或同步冲突会产生两个同 ID 页面，必须额外一套冲突消解。
- **路径编码**：启动时零 IO，文件夹结构本身就是真相。代价是改名后 ID 变化。

## 决策

页面 ID **当前**编码为相对页面根的路径（去扩展名、统一分隔符），但：

- ID 被声明为不透明品牌类型，业务代码不得解析或拼接它。
- 路径与 ID 的互相换算只允许出现在 `src/models/pageId.ts` 一个模块里。
- 改名导致的 ID 变化由操作层主动迁移「展开态」「选择态」「顺序文件条目」三处状态。

## 后果

- 启动扫描是纯内存操作，万级库无白屏风险。
- 将来若要换成 UUID，只需替换 `pageId.ts` 的编码实现，并在操作层加一次元数据写入；其余代码不受影响。
- 代价：外部工具改名（不经插件）时，展开态与顺序条目会离散——这由「结构检查」报告，而不是自动修复。
