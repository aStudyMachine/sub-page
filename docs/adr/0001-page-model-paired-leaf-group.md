# ADR-0001：页面模型为「父页面 / 叶子页面 / 分组目录」三类

- 状态：已采纳
- 日期：2026-11-16

## 背景

最初的设计要求页面必须「目录 + 同名笔记」成对出现（paired 模型），不成对的目录一律视为异常且不显示。

实测本机三个真实档案库（Knowledge 26 篇、Marcus-WIKI 24 篇、My-Resume 329 篇）后发现：**没有任何一个成对的目录**。所有笔记都是「文件夹里放普通 .md」的平铺写法。按原模型，插件在这三个库里会显示一棵空树。

## 决策

在页面根下递归扫描，每个文件夹产出三类节点之一：

1. **父页面**：文件夹里存在同名笔记 → 那个笔记是页面，且是容器。
2. **叶子页面**：任意笔记，没有同名文件夹，或同名文件夹里没有页面 → 它只是页面。
3. **分组目录**：文件夹里没有同名笔记，但含有页面 → 只是容器，不是页面。

不含任何页面的文件夹作为**忽略目录**默认隐藏。

同级的 `名称.md` 和 `名称/` 各有独立的页面 ID。开启「显示空目录」时，空目录与同名笔记都可以出现在树中。叶子页面首次接收子页面时，可复用同名空目录并将原笔记移入。已有其他内容的同名目录保持独立。

## 后果

- 现有档案库零迁移、零改动即可成树，这是本插件的采用门槛所在。
- 页面模型仍只有一种（页面），「配对」退化为一个**可选升级动作**，不是页面存在的前提。
- 代价：同一目录下「笔记」与「文件夹」的语义需要严格约定，扫描器必须处理同名冲突与大小写冲突，复杂度上移到 `pageScanner`。
- 代价：「父页面」的子页面集合由文件夹内容决定，用户不能只靠元数据改变结构。
