# ADR-0004：页面顺序随插件配置保存

- 状态：已采纳
- 更新：2026-11-20

## 背景

需要支持手动拖拽排序。顺序**无法从文件系统推导**，必须持久化。候选位置：

1. 父页面的 frontmatter（每层一个文件）。
2. 页面根下一个集中的顺序文件。
3. 插件配置目录中的独立顺序文件。
4. 文件名数字前缀。

## 决策

采用 **3**。手动顺序属于 Sub Page 的视图状态，由插件目录中的 `order.json` 独立保存。文件的 `roots` 按页面根路径分组，每组以作用域 ID 为键、子项名称数组为值。

- 存名称而非索引：改名只需替换一个元素，移动只需跨数组搬运，不存在间隙索引与重排风暴。
- 未列出的子项按自然排序排在后面，因此手工新建的文件不会消失。
- 某个页面根还没有记录时，首次打开会读取该根的 `.subpage-order.json`，写入并校验新文件。旧文件原样保留。新文件里的空记录也有效，可防止重新导入旧排序。
- 插件顺序文件损坏时保留文件，报告问题并退回名称排序，避免覆盖其他页面根的记录。
- 迁移先校验临时文件。目标文件尚不存在时，将临时文件改名到目标路径，避免读到写了一半的文件。目标文件已有其他页面根时，在宿主的 `DataAdapter.process` 回调中核对内容仍与迁移前一致，再写入合并结果。
- 同一顺序仓储将重载和「修改、持久化、更新内存」放入同一队列。仅给写盘排队会让一场在途重载覆盖刚修改的内存顺序，导致树和磁盘不一致。

## 后果

- 一次拖拽只写一个文件，写入可防抖合并。
- 与其他层级无关，新增/移动页面不需要批量改写多篇笔记。
- 代价：顺序与页面集合分离，外部改名会造成顺序条目孤立——由结构检查报告，未列出者自然排到后面，不阻断使用。
- 跨设备需要同步插件目录中的 `order.json`。复制笔记到其他库时，需要同时迁移所需的排序记录。
- Obsidian 的常规 Vault 文件事件不覆盖插件配置目录。外部同步后，运行「重建页面索引」或重启应用即可读入顺序。
