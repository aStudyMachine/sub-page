# ADR-0004：页面顺序集中存放在页面根的一个文件中

- 状态：已采纳
- 日期：2026-11-16

## 背景

需要支持手动拖拽排序。顺序**无法从文件系统推导**，必须持久化。候选位置：

1. 父页面的 frontmatter（每层一个文件）。
2. 页面根下一个集中的顺序文件。
3. 插件配置目录里的 `data.json`。
4. 文件名数字前缀。

## 决策

采用 **2**：`<页面根>/.subpage-order.json`，一个文件记录所有作用域的次序；键是作用域 ID，值是名称数组。

- 存名称而非索引：改名只需替换一个元素，移动只需跨数组搬运，不存在间隙索引与重排风暴。
- 未列出的子项按自然排序排在后面，因此手工新建的文件不会消失。
- 文件随笔记一起被 git 与同步盘带走；文件名以点开头，宿主文件浏览器不显示，不干扰用户的目录规范。
- 解析失败时备份原文件、退回名称排序、报一条可点击的警告，**绝不因此拒绝显示树**。

## 后果

- 一次拖拽只写一个文件，写入可防抖合并。
- 与其他层级无关，新增/移动页面不需要批量改写多篇笔记。
- 代价：顺序与页面集合分离，外部改名会造成顺序条目孤立——由结构检查报告，未列出者自然排到后面，不阻断使用。
- 代价：3 与 4 被放弃。3 会在目录被复制到其他库时丢失顺序；4 会污染文件名并破坏既有命名规范。
