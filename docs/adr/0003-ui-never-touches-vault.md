# ADR-0003：界面层永不直接访问档案库

- 状态：已采纳
- 日期：2026-11-16

## 背景

侧栏树、正文中的子页面列表、命令、设置页都要读写页面。如果各自直接调用档案库 API，删除确认、失败补偿、事件抑制、索引刷新这些逻辑会被复制四份，且必然走样。

## 决策

- 界面组件（视图、行、卡片、菜单、弹窗）只依赖**页面服务**，不出现任何档案库或文件管理器的直接调用。
- 页面服务以下是「操作层 → 仓储层 → 适配层」，适配层是唯一与宿主 API 接触的地方。
- 操作层每个动作统一为四段式：**校验 → 执行 → 刷新 → 补偿**，并返回结果类型而不是抛异常。
- 适配层被抽象成接口，测试用内存假库实现同一接口。

## 后果

- 侧栏与正文块共享同一套行为，不会出现「侧栏能改名、正文块不能」的不一致。
- 全部结构与操作逻辑可在 node 环境下单测，不需要启动 Obsidian。
- 代价：多一层间接，简单读取也要绕一圈；为此页面服务提供同步读取快照的方法，避免无谓异步。
