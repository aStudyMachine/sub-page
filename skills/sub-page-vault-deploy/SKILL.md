# 部署 Sub Page 到本地笔记库

1. 在仓库根目录执行。用用户指定的库名或路径定位目标。库名解析有歧义时，先核对注册路径，再用明确的路径部署。检查工作区改动，确认本次部署的源码范围。
2. 用 `npm run deploy -- "<库名或路径>"` 执行全量测试、构建和部署。仅更新已安装插件的 CSS 时加 `--css-only`。已验证当前源码对应的构建产物时，可以加 `--no-check`。参数和备份规则见 [部署到本地库](../../CONTRIBUTING.md#部署到本地库)。
3. 核对命令退出状态、实际目标路径、SHA-256 结果与备份路径。部署脚本负责备份、写入校验和失败回滚。命令失败时先查回滚结果，再决定是否重试。
4. 按用户授权重载插件。涉及建页、拖放、排序等写库验收，使用 [手动验收清单](../../CONTRIBUTING.md#手动验收清单) 的样例库。报告实际完成的验证，分别说明测试、产物校验、插件重载和 Obsidian 内的行为验证。Chromium 样式夹具和宿主 API 模拟只覆盖各自的验证范围。
